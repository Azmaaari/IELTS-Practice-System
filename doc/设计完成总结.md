## 🗂️ 核心架构设计

### Store架构（4个Store）

```
stores/
├── examStore.ts      → 题库状态（manifest、文章缓存）
├── practiceStore.ts  → 练习会话（答案、计时器）
├── historyStore.ts   → 练习历史（IndexedDB操作）
└── userStore.ts      → 用户设置（主题、字体）
```

**特点**:
- 使用 Composition API 风格
- practiceStore 和 userStore 持久化到 localStorage
- historyStore 操作 IndexedDB

---

### 路由架构（9个主要路由）

```
/                           → 首页Dashboard
/search                     → 搜索与浏览
/practice/:id               → 单篇练习
/practice/full-test/confirm → 套题确认
/practice/full-test         → 套题练习
/history                    → 练习历史列表
/history/:sessionId         → 历史详情
/stats                      → 统计分析
/settings                   → 设置
```

**特点**:
- 懒加载所有页面组件
- 路由元信息（标题、是否缓存）
- 全局导航守卫

---

### 类型系统（3个核心类型文件）

```typescript
types/
├── exam.ts       → 14种题型、文章、Manifest
├── practice.ts   → 会话、答案、高亮、评分
└── history.ts    → 会话记录
```

**特点**:
- 完整的题型类型定义
- 联合类型确保类型安全
- 与JSON数据结构一致

## 📝 设计决策说明

### 为什么选择 Composition API？

- ✅ 更好的TypeScript支持
- ✅ 逻辑复用更灵活
- ✅ 代码组织更清晰
- ✅ Vue 3推荐方式

### 为什么选择 Tailwind CSS？

- ✅ 快速开发
- ✅ 响应式设计简单
- ✅ 样式一致性好
- ✅ 打包体积小（按需）

### 为什么选择 Dexie.js？

- ✅ IndexedDB的Promise封装
- ✅ TypeScript支持好
- ✅ 查询API简单
- ✅ 支持大量数据

### 为什么分4个Store？

- ✅ 职责分离明确
- ✅ 易于维护和测试
- ✅ 按需持久化
- ✅ 性能更好（不同Store可独立更新）

## ⚠️ 注意事项

### 开发过程中

1. **类型安全**: 充分利用TypeScript，避免使用 `any`
2. **组件复用**: 相似功能抽取为composable
3. **性能优化**: 使用懒加载、虚拟滚动等技术
4. **代码规范**: 遵循ESLint和Prettier配置

### 数据处理

1. **答案字段**: 开发时保留，生产时可选择性移除
2. **数据混淆**: 后续实现，不影响开发
3. **缓存策略**: 合理使用内存缓存和持久化

### PWA配置

1. **先开发功能**: PWA最后配置
2. **离线测试**: 使用Chrome DevTools的Offline模式
3. **Service Worker**: 使用Vite Plugin PWA自动生成
